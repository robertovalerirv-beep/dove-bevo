# App presentation adaptation — 1 November 2026

The app's visitor-only, nonce-bearing presentation bundle adapts the existing website controls without changing the website or backend. The drink selector exposes the existing checkbox group as a horizontally scrollable multi-select. A selected item cannot be removed when it is the final choice because the website's handler still enforces that rule. On a venue receipt, the first price remains prominent; other existing price rows retain their date and freshness information and offer an accessible expansion button for their original confirmation, change and report actions. The leading row is restored when the selected drink changes; toggle labels follow the site language. The price form retains its original input, currency, icon, validation and submission controls in a more compact layout.

The app-only adapter sets the document theme to light and emits the website's existing `themechange` event so that the map can update its own style. A bounded observer handles changes to the theme, the menu's hidden attribute and dynamic receipt rows; page teardown disconnects it. These changes are installed only after the visitor URL, frame, shell, response nonce and applied CSS checks succeed. They do not create public content, fetch data or add storage. When installed by the native container at document start, the early guard registers before website listeners and activates only after the visitor stub and its brand links are present. It corrects the theme before later listeners receive a theme-change event. The site may preload its dark static image before the visitor shell is identifiable. The finish-time adapter remains a fallback on platforms without document-start support; it cannot rule out an already in-flight dark map style. Native installation and timing require device verification.

This is an adaptation of existing functionality, not a claim of reference-image fidelity. The website's actual map markers, search, venue information and price data remain authoritative. The reference's venue photographs, photo upload, payment-date choices, discovery screen and image-sharing flow are not supplied by these changes. Node fixture tests exercise installation, theme enforcement, lifecycle and real-action expansion. An optional headless browser test uses real Preact keyed rows to check promotion, focus, input selection and language updates; visual layout, map style and native accessibility still require actual Android and iOS WebView verification.
