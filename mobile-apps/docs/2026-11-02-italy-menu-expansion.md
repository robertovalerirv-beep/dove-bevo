# Italy first menu expansion

The owner removed the Google review minimum on 2 November 2026. Research and
new menu-price cohorts must not exclude a venue because it has fewer than
101 reviews or because no Google review count is available.

Priority: major Italian cities, especially Milano, Roma, Torino and Napoli;
then wider Italy; then European capitals. This is a one-off initial
population. Customer prices and subsequent corrections retain their existing
behaviour.

## Schema 4

The additive legacy-Italy manifest format has no Google fields. It requires
official source evidence, an exact current catalogue identity, EUR, an
unconditional normal price, the literal menu item and an honest serving note.
Unknown volume is recorded as not stated; it is not inferred.

The current legacy table stores one scalar per venue/category/band. Therefore
this first format rejects conditional prices, happy-hour rows, conflicting
generic-category prices, unsupported categories and unrepresentable serving
variants. It never chooses a cheap premium variant, clamps a real price,
invents a payment date or replaces a customer contribution.

Menu item and serving notes are audit-ledger evidence, not new legacy-table
columns or a claim that the old UI displays menu provenance. Existing schema
1/2 evidence remains historically validated. The separate fixed rendered
Mosto adapter remains preserved on its existing branch.

Each cohort is at most 200 records. Source bytes or normalized markup text
are pinned, current public catalogue version and exact identity are checked,
and the existing domain/Worker/D1 binding is attested. Atomic guards for
current prices in every status, history, reports and hidden venues are
unchanged. Audit precedes an exact-hash apply; public read-back establishes
the actual imported count. A lead, dry run, skipped record or local file is
not an import.

## Wider catalogue follow-up

Existing Italy catalogue identities can be populated immediately through the
reviewed legacy path. New app-only no-Google catalogue entries need a
backward-compatible catalogue and client rollout: the installed v1 readers
still require the historical Google-shaped record. Do not insert dummy
review counts or publish a catalogue that breaks installed clients.

The active OneDrive repair requested a quiet-folder hold. During that hold,
research and remote GitHub source operations use memory only; no project
checkout, build, download or generated file is created outside the selected
project folder.
