# Bounded public city inventory

Run `python -B mobile-apps/tools/menu-seed/inventory_city_prices.py` once to print JSON for Milano, Roma, Torino and Napoli. Select up to four other published OSM place IDs with repeated `--city ID`. Exit zero means every selected city reconciled successfully; exit one retains partial results and errors. This command only reads public data. It does not discover menus, determine import eligibility, import prices, authenticate, schedule work or change the website.

The tool reads `/api/health`, versioned `places.json`, candidate `v/{geohash5}.json` cells and `/api/prices/{cell}`, then health again. It permits only those exact paths on `https://www.dovebevo.com`, refuses redirects, disables ambient proxies, uses a 20-second transport timeout and a 2 MiB response limit, and runs at most three GETs concurrently without retries. It never accesses admin coverage. Four cities and 100 candidate cells per city bound a run to at most 803 GETs (two health, one places, up to 400 static and 400 price files).

The static importer assigns each venue to the nearest OSM city or town within 15 km, not a municipal boundary. A spherical 15.01 km bounding box covers the original assignment and coordinate rounding. Each valid venue is filtered by its city-table ID, checked against its geohash cell and deduplicated by OSM key. `count_matches_places` compares the retained unique count with the exact published place total. Overall `complete` additionally requires no fetch or validation errors and unchanged final data version. Missing files and HTML fallback pages are errors, even if the retained count happens to match; they are never interpreted as empty cells. Consequently a legitimate empty-cell HTML fallback can leave this conservative tool incomplete.

The JSON contains each retained venue's exact key, name, cell, city, coordinates and address. Prices count only mapped OSM keys; hidden venues, quarantined tuples, pending and approved user venues are excluded. Per-drink counts deduplicate venues across normal and happy-hour tuples. A failed price read leaves `price_read_complete` false and `hidden` unknown (`null`); an empty retained price list then does not prove absence. Valid partial observations remain available alongside errors. Requests are sequential snapshots across a bounded interval, not an atomic database snapshot; unchanged data version does not freeze live prices.

`remaining_menu_eligible` is always null: unpriced records do not establish an available current official menu, safe fee conditions or guarded import eligibility. Existing `discover_menu_links.py`, importer guards, public data and backend contracts are unchanged.

Offline tests: `python -B -m unittest discover -s mobile-apps/tools/menu-seed -p test_city_inventory.py -v`. Tests inject fake GET results and never contact the network.

## Live Windows verification

The first direct health request returned HTTP 403 with the default Python user agent. The same strict public request with the descriptive DoveBevoMenuAudit/1 header returned HTTP 200 JSON. The helper now identifies these bounded public reads; its URL, proxy, redirect, MIME and response-size restrictions are unchanged. A live inventory also exposed cp1252 stdout failure on a real Unicode venue name. CLI JSON now escapes Unicode losslessly, with a regression that round-trips Unicode through a Windows legacy output encoding. All 15 inventory and 11 discovery tests pass.

The repeat read on 2 November 2026 retained data version 20261101 before and after, and matched each full published static count: Milano 682, Roma 547, Torino 359 and Napoli 215 (1,803 total). Observed priced venues / category rows were respectively 29/71, 4/14, 9/36 and 5/14. Known public unpriced venues were 653, 543, 350 and 210. These are menu-research targets, not verified import eligibility or a complete price-history count. Conservative complete remains false: 8, 22, 21 and 25 surrounding-cell requests respectively failed, even though catalogue counts reconcile. No failed cell was treated as empty or absence evidence. The summary is retained in mobile-apps/data/italy-city-inventory-20261102.json; the command can produce full exact venue targets locally.
