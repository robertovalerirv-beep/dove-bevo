# Android quality and external production protection

The required `android` job and release dependencies remain unchanged. Build, lint, JVM tests, debug APK and instrumentation APK assembly are mandatory. In the existing owned ephemeral no-window AVD lifecycle, the smoke runner installs both APKs and explicitly selects five owned instrumentation classes: NativeUsability (21), Recommendations (6), Favorites (5), Discovery (2) and EuropePrices (1). All 35 starts and passes plus the final `OK (35 tests)` and successful instrumentation completion are required. Failures, errors, skips, assumptions, missing/duplicate cases and unexpected classes fail the job. `PublicBrowseRuntimeTest` is not included in that fixture process.

After owned instrumentation succeeds, the runner force-stops the target package. The existing unmodified production launch then starts in a fresh process, without fixture interceptors. The original native rules/privacy/decline, live city search, Milano map, resume and restart checks remain. Private SDK/ADB ownership, diagnostics and cleanup guards remain mandatory. There are no protection changes, UA/IP spoofing, checkbox clicks, CAPTCHA solving, automatic page reloads or request retries.

Only during a named public probe stage, after owned cases passed, can the runner recognize the exact observed Cloudflare challenge: an app-owned WebView subtree containing the fixed production host, security-verification heading, human-verification checkbox and Cloudflare attribution. A generic timeout, HTTP failure, app crash or missing search control is not a recognized block. The original challenge XML and PNG are saved separately with hashes and the stage, then `PublicProbeBlocked` is raised. The receipt says `result: blocked`, `blocker: cloudflare_challenge`, and `public_probe.result: blocked`; it never calls the public probe passed.

Only the explicit PR wrapper, also checking the repository and `pull_request` event, may turn that exception into a warning and successful **quality job**. It first re-reads the receipt, checks the complete owned result, verifies original artifact hashes and positive challenge XML, and requires clean cleanup and diagnostics. Receipt write/read-back failures, missing or altered evidence, cleanup failure and every unexpected exception stay fatal. The wrapper does not use `continue-on-error`, force a status, or replace the saved blocked result with success.

Release/upload tags receive no exception: the default runner still fails for a recognized public block. A green PR quality job with this warning is source-quality evidence plus an explicitly blocked external probe, not a public launch, physical-device result or passing production browse test. Existing immutable beta/release tags and previous receipts are unaffected. Any future release exception would need a separately reviewed policy and current evidence; none is introduced here.

The artifact contains `owned-instrumentation.json`, `smoke-result.json`, original `public-blocked-ui.xml`/`public-blocked.png` when relevant, final XML/PNG and existing startup/command diagnostics. The implementation lane validates the classification using local doubles and real receipt files only; it does not execute an emulator, public request, cloud workflow, tag, push or release action.

Before strict owned-test parsing, `emulator-startup.json` now retains `owned_instrumentation` stdout/stderr original byte counts and SHA-256 hashes, redacted UTF-8 heads and tails limited to 16 KiB each, and the command exit code. Redaction runs before window selection so a tail cannot expose the middle of a key block or credential line. `sanitized_bytes` describes the sanitized stream; `truncated_bytes` counts its omitted middle bytes, and short heads/tails may overlap. Parsing still uses the complete original bytes and the same mandatory 35-case criteria. Failed parsing/commands also attempt one filtered logcat dump (last 300 lines, 15-second timeout, AndroidRuntime/TestRunner/chromium/libc/DEBUG/System.err tags only) while the private ADB server remains alive. Its retained streams use the same redaction/size limits. No raw streams or credentials are printed. Diagnostic failures preserve the original test/command exception; a diagnostics write failure on an otherwise passing owned run remains fatal. These details use an already uploaded artifact and do not change the CI exception or public-probe policy.
