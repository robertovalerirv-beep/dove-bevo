# iOS European native prices

The native Preferiti and Scopri readers use the owner-approved app catalogue and currency-aware mobile GET API. Roberto's website, legacy tuples, price storage and native bookmark file format remain unchanged. The European frontend and deployment are separate integration responsibilities.

`EuropePrices.swift` validates a fresh JSON catalogue (2 MiB maximum), canonical OSM identity, unique keys, actual geohash coordinates, supported country bounds, currency, names, review-count threshold and source-check date. Mobile cells must match that exact catalogue version and cell. The reader checks all variants, currency, category bounds, serving unit/volume, dates, revision and provenance, including the immutable source SHA-256. Hidden and legacy keys have exact cell scope. A failed catalogue never authorizes a foreign legacy-euro fallback; an explicitly known key in another cell cannot be used under a different bookmark identity.

Existing `FavouritePrice` parsing stays strict and unchanged. `EuropePrice` is separate and is never coerced into a legacy EUR tuple. Snapshots attach the optional European values alongside their original legacy containers. All active drink/band variants remain visible: 250/500 ml beer and 175/250 ml wine are separate rows. Sorting groups by actual currency and serving before sorting amounts within a group; no conversion or cross-size bargain is implied. Legacy EUR prices explicitly show `Formato non dichiarato` and form their own comparison group. Quarantined prices do not enter native comparisons.

Online menus retain null customer `observed_on`, while the card displays `Fonte verificata il`, the menu item/conditions and source host. The full source URL and hash remain in the typed model; opening the venue shows its link in the mobile web detail. A menu check more than 90 days old shows `Menu da riverificare`. Customer rows use their observation day; confirmations have their own date. A later menu confirmation cannot manufacture a customer observation or silently refresh the source-check date. No votes, visits, prices or paid dates are generated by the native reader.

Production defaults enable Europe even with an injected transport. Existing legacy-focused tests explicitly use `includeEurope: false`; new default-path tests exercise the catalogue and mobile endpoints. Each refresh reads the catalogue once, shares the existing global 60-second deadline and uses at most three active cell slots. Relevant legacy/mobile reads run sequentially inside a cell. Transport remains read-only, ephemeral, cookie/credential-free, redirect-refusing and byte-bounded. Retiring a request clears pending tokens before canceling handles, so late callbacks cannot restart work or publish results. A successfully validated catalogue establishes a complete-empty foreign cell; a failed catalogue remains unavailable.

Private bookmark identity remains canonical `/bar/key?c=cell`, with actual native loading translated to `/mobile/`. Native favourites/discovery do not persist server price/name updates into the bookmark file. Recommendation resolver and public sharing changes belong to their separately owned integration lanes.

Verification: Windows source guards plus independent source review; the new Swift tests cover real parser failures, GBP/EUR and serving groups, HH, null menu observation dates, old/fresh menus, hidden/version mismatch, production-default transports, an actual three-slot pool/deadline and owned UIKit saved/discovery rows. Windows has no Swift/UIKit compiler. These tests require the coordinator's fresh hosted Mac gate before any compiled/runtime claim or store release.
