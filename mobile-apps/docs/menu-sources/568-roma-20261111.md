## Evidence and boundaries

The 50 proposed rows are named drink/price facts from the owner's current
`Da Bere` menu. They include one explicit 0.50 L draft beer, three named beer
cocktails, four explicitly priced Spritz variants, Hugo, a 0.50 L Bad Day
Spritz, named soft drinks, absinthes, spirits and liqueurs. Slash-separated
options are split only when the menu displays one price for the listed
alternatives. The source names, printed amounts and any printed serving are in
each row's `evidence_ref`. A local check found all 50 printed name and amount
pairs within their menu sections; the importer manifest validator accepted
all 50 rows.

Conservative exclusions:

- Variable draft beers listed as “altre” with conditional availability, and
  bottled beer varieties left to a blackboard.
- Paired wine prices `5.00/15.00€` without an explicit glass/bottle serving
  mapping in this menu.
- Generic `Cocktail` €6 for which guests are told to ask for the list and
  whose price varies with the liquor chosen.
- The four-beer tasting set for two, because the menu does not clarify whether
  €8 is per set or per person.

No mandatory service fee statement was found on the owner menu. The manifest
therefore leaves fee coverage **unknown**; it does not claim fees are absent.
Unclassified cocktails and spirits remain uncategorized rather than being
mapped to an unrelated drink filter. No visit date, customer purchase,
recommendation, Google review count or drink photo is inferred.

source-only merge. Then a protected production audit must verify the current
source, static identity, production binding and eligible rows before a
separate guarded seed tag. Public app-v2 API readback must match every
