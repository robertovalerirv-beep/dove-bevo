# App-only HTTPS presentation

This entry supplies a separate white mobile layout, compact venue and price sheets, drink chips, and map price pins. Italy retains the existing App's data and contribution logic. The isolated Europe adapter uses the separately approved mobile catalogue and currency-aware price API, preserving the website's interface and legacy price semantics. This frontend change does not edit the public website source, Worker or schema.

`npm run build` builds the existing website first, then stages only `/mobile/index.html` and `/assets/mobile/*`. Staging hashes every pre-existing website artifact and fails if one changes. App and map seams are compile-time transforms pinned to reviewed LF-normalized source hashes; upstream source changes require an explicit review and new pins. No browser-history prototype or shared website runtime is patched.

Routes remain real HTTPS assets: `/mobile/` for the map and `/mobile/?path=%2Fbar%2Fn123&c=u0nd9` for a venue. Private native bookmarks retain canonical `/bar/n123?c=u0nd9` identity. Public links for European catalogue venues must use the real `/mobile/` entry, because the unchanged legacy website cannot resolve those foreign venues; legacy Italian public links retain their original canonical URL. Native apps must validate and translate these routes, verify the document's `data-dovebevo-mobile-shell="1"` marker, and handle a missing marker before switching their default entry. An existing root-scoped website service worker can still return its original cached homepage on an offline navigation; this entry does not unregister it or erase browser storage.

The map preserves the existing data selection, price tiers, normal/HH preference and attribution. A price pin's head and geographical tip share one hit target; overlapping hit layers dispatch a single venue selection. HH remains a separate label. Neutral prices remain neutral when there is insufficient evidence for a relative-price tier.

The Spritz image is original generated illustrative drink photography, not a photo of a particular venue or evidence of its serving. It is used only for the Spritz category. It was generated from an unbranded glass of orange spritz with ice and an orange slice on a white background, then encoded as JPEG quality 80 at the original 1024 x 1536 dimensions. ## European catalogue and prices

`AppHost` validates `/mobile-data/catalog.json` and chooses an isolated `EuropeApp` for actual catalogue venues/cities. City centres are calculated only from catalogue venue coordinates, and an incoming `at` must be within 40 km of a catalogue point. No synthetic municipality ID or guessed venue is created. The copied mobile-only `SearchSheet` adds these real catalogue results beside the original Italian search. Crossing into the original Italian app performs a document navigation, avoiding a second retained map and the original map's window listeners. No runtime fetch/history prototype is patched.

Currency, drink, normal/HH band and exact serving identify every comparison. GBP is displayed as pounds and EUR as euros without conversion. Draft beer and water require the actual ml volume; a 400 ml beer is never compared with a 568 ml beer. Wine is a glass with optional declared volume. Other categories remain a single drink. All variants remain visible on a venue, and the map/list filter explicitly chooses one serving. Only active equivalent rows enter map prices and same-cell deal tiers; quarantine rows remain visibly awaiting confirmation. Sparse data stays neutral.

Online menu rows show their source-check date, source URL and literal menu item/conditions. Their `observed_on` remains null; checking a menu is never presented as a customer visit/payment. Customer rows show the server-assigned observation date separately from any later confirmation date. Legacy Italian prices retain their original generic dated presentation.

Customer submissions use the original protected browser session/Turnstile flow and the additive `/api/mobile/prices` routes. A queued submission holds an immutable venue/currency/serving target, offers the original five-second undo timer, and retains a reachable Undo when switching cities. Clients cannot submit a source URL, a menu hash, a sourced-price claim or a historical paid date. Confirm/report requests carry the viewed revision, and a conflict cannot optimistically increase totals. Browsing sends no precise location to the price API.

Read responses have strict schema, catalogue-version, currency and identity checks with a 2 MiB bound. Lifecycle cancellation and a manual 20-second deadline fence price/status reads, using Safari 16.4-compatible APIs. A late previous-city response cannot render into another currency scope. Failure remains unavailable rather than a successful zero-price result. Retry reloads the document/catalogue together, allowing recovery from a new deployment version. The native map DOM contract keeps fixed five-decimal `data-center`, one-decimal `data-zoom`, actual `data-selected`, `h2.scontrino__name` and `.bar__addr`.

The catalogue is curated coverage, not a claim that every major European venue has been added. Native favourites/discovery need their own typed catalogue adapter; legacy EUR readers must not consume these rows. Public drink recommendations likewise need a trusted-catalogue resolver for foreign venues or an explicit unavailable state; this frontend never invents vote totals.

## Verification

- `node --test mobile-apps/web/tests/*.test.mjs mobile-apps/web/components/tests/components.test.mjs` after a full build. The browser uses Playwright Chromium, or the explicitly supplied `DOVEBEVO_BROWSER` executable. All API data is isolated; legacy fixtures block writes, and European write/session cases are intercepted and answered locally. Unknown requests are blocked. Fixture screenshots are not proof of live basemap or installed-phone fidelity.
- `npx tsc -p mobile-apps/web/tsconfig.json --noEmit` verifies the app entry and components, in addition to the existing repository gates.
- Existing security E2E checks exercise the actual workerd asset path, production nonces/headers and unchanged website entry.
- Optional visual comparison: run the bundle cases with `DOVEBEVO_LIVE_MAP_STYLE=1` to use the emitted production style and real OpenFreeMap tiles. Venue and price records still belong to the isolated fixture, and all non-GET requests remain blocked.

Real-phone integration, live basemap comparison with the owner's reference, source-reviewed native route translation, and store distribution remain required before release. This source change alone does not update an installed app or establish a public store launch.
